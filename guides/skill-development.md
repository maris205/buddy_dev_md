# Skill 开发阅读路径

依据：[官方技能文档](../docs/skill.md)。本页提供开发步骤和检查建议，不替代原文字段定义。

## 先明确一个可验证任务

写清用户在什么情况下触发技能，需要什么输入，以及输出应当是什么。先选一个可独立完成的任务，例如“把给定材料整理为固定结构的报告”。涉及外部数据时，先决定脚本是否足够，或需要 [连接器](connector-development.md)。

## 组织文件

按原文的 `SKILL.md`、`references/`、`scripts/`、`templates/` 结构组织。不要在主指令中塞入全部平台文档：把与当前任务直接相关的参考资料放在 `references/`，在需要时引用。

字段名称和必填性直接查 [技能原文](../docs/skill.md) 的 Frontmatter 表。表格和示例可能有差异，因此不要仅从示例中推断必填字段；遇到歧义记录具体字段并通过平台解析验证。

## 本地检查建议

- [ ] 输入、输出、触发条件和失败处理已明确。
- [ ] `SKILL.md` 的 YAML 和 Markdown 正文可解析，字段按当前官方表格填写。
- [ ] 引用的资料、脚本、模板均存在，路径与打包结构一致。
- [ ] 脚本的运行命令、参数、依赖、输出格式已说明。
- [ ] 至少实际验证一个正常输入和一个有代表性的错误输入。
- [ ] ZIP 内容与官方结构一致；在平台上验证解析和调用。

上述清单中的测试安排是整理者建议。平台解析、运行和发布是否成功，需要真实验证后记录；本知识库尚未执行这些步骤。
